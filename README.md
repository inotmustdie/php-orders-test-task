# Тестовое задание: обработка заказов

Скрипт читает список заказов из JSON, валидирует данные и выводит
статистику по оплаченным заказам. Дополнительно — группировка по статусам
и сохранение сводки в `result.json`.

## Требования

- PHP 8.1 или выше
- Никаких внешних зависимостей

## Запуск

```bash
php orders.php orders.json
```

Путь к файлу можно не указывать — по умолчанию берётся `orders.json`
из текущей директории:

```bash
php orders.php
```

После выполнения рядом появится `result.json` со сводкой.

## Пример результата работы

Для исходных данных из задания (`orders.json`):

```
Количество оплаченных заказов: 3
Общая сумма оплаченных заказов: 4500
Самый дорогой оплаченный заказ: № 103 на сумму 3000

Группировка по статусам:
  paid: 3
  pending: 1

Результат сохранён в result.json
```

Содержимое `result.json`:

```json
{
    "paid_count": 3,
    "paid_total": 4500,
    "most_expensive_id": 103,
    "groups": {
        "paid": 3,
        "pending": 1
    },
    "warnings": []
}
```

## Обработка ошибок

Валидация не «роняет» скрипт на первом же плохом заказе. Все проблемы
собираются в массив `errors`, выводятся в `STDERR` (чтобы не смешивать
с полезным выводом), а обработка валидных заказов продолжается.

| Ситуация | Поведение |
|---|---|
| **JSON не декодируется** | `json_decode` вызывается с `JSON_THROW_ON_ERROR`, ловим `JsonException`, выводим сообщение и завершаем с кодом `1` — обрабатывать нечего. |
| **Отсутствует обязательное поле** | Заказ пропускается, в `errors` добавляется предупреждение с номером заказа и списком отсутствующих полей. Остальные заказы обрабатываются. |
| **Сумма отрицательная или неверного типа** | Заказ пропускается с предупреждением. Проверяем `is_int`/`is_float` (строки вроде `"1500"` отбрасываем) и `< 0`. |
| **Неизвестный статус** | Заказ пропускается с предупреждением. Допустимые статусы: `paid`, `pending`, `cancelled`. |
| **Нет валидных заказов вообще** | Выводим сообщение в `STDERR` и завершаем с кодом `1`. |
| **Файл не найден / недоступен** | Выводим сообщение в `STDERR` и завершаем с кодом `1`. |

Пример вывода при наличии ошибок (в `STDERR`):

```
Предупреждения:
  - Заказ #2: отсутствуют поля: amount
  - Заказ #5: отрицательная сумма (-100)
  - Заказ #7: неизвестный статус 'refunded'
```

## Принятые решения

- **`JSON_THROW_ON_ERROR`** — чище, чем проверять `json_last_error()` вручную.
- **`array_values` после `array_filter`** — чтобы индексы оставались
  последовательными и код был предсказуемым.
- **`STDERR` для предупреждений** — полезный вывод (`STDOUT`) можно
  безопасно парсить, не отфильтровывая сообщения об ошибках.
- **Деньги как числа** — в тестовом задании суммы целые; в реальном
  проекте хранил бы в копейках (`int`), чтобы избежать ошибок округления
  с `float`.
